# Conformance fixtures

Every folder here holds one small test bundle and the result a correct reader
must produce. Together they are a test suite that **any** OpenWaymark
implementation can run, in any programming language.

They are also a short course in how files attack the programs that open them.
Each section below explains a family of attacks or mistakes, why it matters,
and which rule in the [specification](../spec/openwaymark.md) stops it.

## How to use them

Each fixture folder contains:

- `input.waymark` (an archive) or `input.yaml` (a text bundle): the bundle to
  test;
- `expect.json`: what should happen.

```json
{
  "description": "An entry name escapes the archive with '..'.",
  "format_version": "0.1",
  "mode": "validate",
  "outcome": "reject",
  "rules": ["OWM-PATH-001"]
}
```

| Field | Meaning |
|---|---|
| `outcome` | **Normative.** `accept` means a conforming reader accepts the bundle; `reject` means it must reject it. |
| `rules` | **Informative.** The rule identifiers the reference engine reports. Another validator may word or number its findings differently, but it should reject for the same reason. |
| `mode` | `validate` for conformance only, or `lint` to also run the recommended lint checks. Lint findings are warnings and never change the outcome. |

To run them against the reference engine, run `pnpm test` from the repository
root. To run them against your own implementation, loop over the folders, feed
each input to your reader, and compare its verdict with `outcome`.

The fixtures are generated by [`tools/generate-fixtures.mjs`](../tools/generate-fixtures.mjs),
so every byte is reproducible. A test fails if the committed files and the
generator ever disagree. To add a fixture, add it to the generator, run
`node tools/generate-fixtures.mjs`, and commit the result.

Every fixture is harmless and small. The largest file is about 200 KB, and the
"bombs" are a few kilobytes that would only *become* large if a careless
program expanded them.

## Lesson 1: archives that lie about their contents

A ZIP file is a list of files, with a table of contents (the **central
directory**) at the end. Each file also has its own small header (a **local
header**) in front of its data. A program reading the archive trusts these
headers. Attackers make them lie.

| Fixture | The trick | Why it is dangerous | Stopped by |
|---|---|---|---|
| `zip-traversal`, `zip-absolute-path`, `zip-backslash` | A file named `../../evil.png`, `/etc/cron.d/evil`, or `assets\gray.png` | **"Zip slip."** A program that extracts files using their names as paths can be tricked into writing outside the folder it meant to use, and overwrite something important | OWM-PATH-001 |
| `zip-symlink` | An entry that is a symbolic link, a pointer to another file such as `/etc/passwd` | Extracting it creates a shortcut to a sensitive file, which the app might then read or overwrite | OWM-PKG-009 |
| `zip-local-central-mismatch` | The table of contents says `assets/gray.png`, but the file's own header says `assets/evil.sh` | Two programs reading the same archive see different files. A checker approves one thing while the app opens another | OWM-PKG-007 |
| `zip-hidden-gap`, `zip-prepended-data`, `zip-trailing-data` | Bytes hidden between, before, or after the real entries | Hidden data can carry a second payload. A **polyglot** file is valid as two formats at once, such as a script that is also a ZIP | OWM-PKG-006, OWM-PKG-002, OWM-PKG-001 |
| `zip-duplicate-name`, `zip-case-collision` | Two `study.yaml` entries, or `assets/gray.png` and `assets/Gray.png` | Which one wins depends on the tool. On Windows and macOS, case-different names land on the same file | OWM-PATH-002 |
| `zip-unicode-path-extra` | An optional field that gives an entry a second name | Again, different tools show different names | OWM-PKG-011 |
| `zip-encrypted`, `zip-unsupported-method`, `zip64-extra-field` | Encryption, unusual compression, or 64-bit size records | Features that tools support unevenly. A file that one reader opens and another cannot is not portable, and rarely used code paths are where bugs hide | OWM-PKG-004, OWM-PKG-005, OWM-PKG-003 |
| `zip-bad-crc`, `zip-size-understated`, `zip-truncated` | A wrong checksum, a file larger than its declared size, or an archive cut short | Damaged or deliberately misleading data. "Larger than declared" is how some programs are tricked into overflowing a buffer | OWM-PKG-008, OWM-PKG-007, OWM-PKG-002 |

**The general lesson:** when a file can be read more than one way, assume an
attacker chose the way that hurts you. The specification therefore allows
exactly one reading: no gaps, no disagreement, no ambiguity.

## Lesson 2: small files that become enormous

| Fixture | The trick | Why it is dangerous | Stopped by |
|---|---|---|---|
| `zip-compression-bomb` | 2 MiB of zeros compressed to about 2 KB: a ratio of roughly 1,000 to 1 | A **decompression bomb**. Real ones turn kilobytes into terabytes and exhaust a device's memory or storage | OWM-LIM-001, OWM-LIM-002 |
| `zip-too-many-entries` | 2,002 entries | Processing time and memory that grow with the entry count | OWM-LIM-001 |
| `collection-too-many-items` | 10,001 flashcards | The same idea, inside the manifest | OWM-LIM-001 |
| `image-huge-dimensions` | A 100-byte PNG claiming 100,000 × 100,000 pixels | An **image bomb**. Decoding it would need about 40 GB of memory. The engine reads the declared size first and refuses before decoding anything | OWM-IMG-010 |
| `yaml-deep-nesting` | Mappings nested 40 levels deep | Deep recursion can crash a parser | OWM-LIM-001 |
| `yaml-alias-bomb` | YAML aliases, each repeating the one before nine times | The **"billion laughs"** attack. Each level multiplies the size, so a few lines expand to millions of values. OpenWaymark forbids aliases entirely | OWM-YAML-002 |

**The general lesson:** check sizes **while** reading, not after. The engine
decompresses in small steps and stops the moment a limit is crossed, so the
bomb never gets the chance to go off.

## Lesson 3: files pretending to be something else

| Fixture | The trick | Stopped by |
|---|---|---|
| `image-spoofed-type` | A JPEG named `.png` | OWM-IMG-007 |
| `image-not-an-image` | Text that contains an SVG with a script, named `.png` | OWM-IMG-006 |
| `image-svg`, `zip-script-file`, `zip-nested-archive` | An SVG (which can contain scripts), a `.js` file, and an archive inside the archive | OWM-IMG-006 |
| `image-truncated`, `image-corrupt-data`, `image-png-bad-crc`, `image-jpeg-truncated` | Damaged images | OWM-IMG-009 |
| `image-animated-png`, `image-animated-webp` | Animated images | OWM-IMG-008 |

**Why check the content, not the name?** A file name is a claim. The engine
reads the first bytes, the **signature** or "magic number", which says what the
file really is.

**A lesson the browser tests taught us.** Firefox and WebKit draw a PNG with
damaged pixel data without complaining, while Node's decoder rejects it. So
the engine checks image structure itself, rather than relying on whichever
decoder a platform happens to have: PNG chunk checksums, the exact amount of
pixel data, and JPEG end markers. Every platform now gets the same answer.

## Lesson 4: text that tries to become code

OpenWaymark text is Markdown, and the app displays it. If displaying text
could ever *run* it, a bundle could take over the app.

| Fixture | The trick | Why it is dangerous | Stopped by |
|---|---|---|---|
| `markdown-raw-html`, `markdown-event-handler` | `<script>alert(1)</script>` or `<img src=x onerror=alert(1)>` written as plain text | **Cross-site scripting (XSS):** HTML that runs code when displayed | OWM-MD-003, OWM-MD-004 |
| `markdown-javascript-link` | A link to `javascript:alert(1)` | Clicking it would run code | OWM-LINK-001 |
| `markdown-remote-image`, `markdown-data-uri-image` | An image loaded from a website, or embedded as a `data:` URL | A remote image is a **tracking pixel**: it tells a server who opened the bundle, and when | OWM-MD-009, OWM-LINK-002 |
| `markdown-mailto-autolink`, `markdown-http-link`, `url-userinfo` | `mailto:` and `http:` links, or `https://trusted.example.org@evil.example.net/` | That last address goes to `evil.example.net`. Everything before the `@` is a user name, a classic disguise | OWM-LINK-001 |
| `valid-literal-security-text` (**accepted**) | The same attack strings, inside code blocks | Teaching material legitimately contains them. Inside code they are only text, and the reader shows them literally | OWM-MD-005 |

**The general lesson:** do not try to recognize "bad" text. Decide which
constructs are allowed, and treat everything else as inert text. That is called
an **allowlist**, and it is far safer than a list of known-bad things.

## Lesson 5: data formats with sharp edges

| Fixture | The trick | Stopped by |
|---|---|---|
| `yaml-custom-tag` | `!!python/object/apply:os.system`, which tells some YAML libraries to *run a command* while parsing | OWM-YAML-002 |
| `yaml-proto-key` | A key named `__proto__`, which can corrupt every object in a careless JavaScript program (**prototype pollution**) | Stored as ordinary data; OWM-VER-004 |
| `yaml-duplicate-key`, `integrity-duplicate-key` | The same key twice: which value wins? | OWM-YAML-004, OWM-INT-002 |
| `yaml-float`, `version-not-a-string`, `lint-yaml11-ambiguous` | `0.1`, `1.0`, `no`, and dates mean different things to different YAML versions | OWM-YAML-009, OWM-YAML-006, OWM-LINT-012 |
| `yaml-multiple-documents`, `yaml-directive`, `yaml-null-value`, `yaml-malformed` | YAML features with no meaning in a manifest | OWM-YAML-001, OWM-YAML-008, OWM-YAML-011 |
| `encoding-invalid-utf8`, `encoding-control-character` | Broken text encoding, and invisible control characters | OWM-ENC-001, OWM-ENC-002 |

## Lesson 6: honest mistakes

Most problems are not attacks. They are typos, and the validator should explain
them kindly.

| Fixture | The mistake | Stopped by |
|---|---|---|
| `zip-wrapper-folder` | Compressing the folder instead of its contents, so `study.yaml` is inside `my-bundle/` | OWM-PATH-003 |
| `unknown-member` | `explaination` instead of `explanation`. The validator suggests the right spelling | OWM-VER-004 |
| `answer-unknown-choice`, `single-two-correct`, `selection-count-mismatch`, `choice-id-duplicate`, `id-collision` | Answers that do not match the choices | OWM-Q-004 to OWM-Q-006, OWM-ID-002, OWM-ID-003 |
| `version-unsupported`, `version-missing`, `requires-unknown-feature` | A bundle for a format version or feature this reader does not know | OWM-VER-002, OWM-CONF-004, OWM-VER-006 |
| `zip-manifest-wrong-case`, `zip-unexpected-file`, `zip-space-in-name` | `Study.yaml` instead of `study.yaml`, a stray `README.txt`, or a file name with a space | OWM-PATH-003, OWM-PATH-004, OWM-PATH-001 |
| `image-missing-asset`, `image-uppercase-extension`, `text-bundle-asset` | An image that is not in the bundle, a `.PNG` extension, or an image in a single-file text bundle, which cannot carry one | OWM-IMG-001, OWM-IMG-006, OWM-TEXT-002 |
| `collection-no-items`, `collection-uuid-uppercase` | A collection with nothing to study, or an id typed in capitals | OWM-COL-002, OWM-COL-004 |
| `markdown-heading-in-item` | A heading inside a flashcard | OWM-MD-007 |
| `language-part-malformed`, `extension-bad-namespace` | `spanish_mx` instead of a language tag such as `es-MX`, or an extension key that is not a domain name | OWM-CONT-003, OWM-EXT-001 |
| `integrity-file-changed` and the other `integrity-*` fixtures | Editing a packed bundle by hand, so `integrity.json` no longer matches | OWM-INT-002 to OWM-INT-004 |

## Accepted on purpose

The `valid-*` and `lint-*` fixtures must be **accepted**. They prove that the
rules are not so strict that they reject real bundles:

- macOS and Windows metadata files are tolerated with a warning;
- data descriptors, written by streaming tools, are accepted;
- a byte order mark is accepted;
- signature data reserved for the future is ignored;
- a valid integrity file is checked and accepted.
